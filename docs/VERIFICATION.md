# Verification scope

This is implementation testing and a local correctness review, not an independent audit. The separate workflow review must examine accepted source and the later manifest. No claim of independent agents or live oracle execution is made here.

Final local checks: `forge build` succeeded with Solidity 0.8.26; `forge test` passed **86 tests across nine suites**, with no failures or skips, using the required seed; `forge fmt --check` passed. The invariant suite completed 24,576 calls with zero handler reverts. Weir's deployed runtime is **23,817 bytes** and LaunchToken's is **1,723 bytes**, both below the 24,576-byte limit; both runtime opcode tests passed. Both exported ABIs match the compiler artifacts. Weir has exactly six flat constructor inputs; LaunchToken has none. The creation/runtime artifacts have no library link references. These are the contributor's local results, not independent verification. The two supplied proofs of this revision (`Proof_9dfcd6fccfcf`, `Proof_21fa62bab90d`) were copied unchanged into scratch space, failed on the starting tree and pass on this one; the earlier recovery proof remains disputed as described below.

Foundry's remaining lint notices concern Solidity's default-zero local initialization, deliberate per-byte validation reverts, the short literal action-to-bytes32 cast, guarded events after external calls, and timestamp-based stream/deadline arithmetic. They were inspected in the local review; the build has no compiler errors. Test timestamp optimizer notices were addressed with Foundry clock accessors.

Arithmetic, bond-routing, and ASCII/JSON fuzz tests each use 1,000 runs. The invariant campaign uses 256 runs of 96 calls with fail-on-revert enabled (24,576 handler calls). Its model transfers value between earned and unearned buckets when time advances instead of duplicating the contract's snapshot-debt calculation. About a third of its disputed streams are never accepted by their recipient, and the record model mirrors the contract by counting only accepted streams. A deterministic handler test exercises every dispute exit as well.

The required fuzz seed is `0x56b8ba92d00416c8f19c62ec194b5746c200a1ddf94687c04427d28eb99f95dd`. The fixed-vector test is independent of signatures generated from the implementation's own digest. The canonical vector is a bytes32-list answer about a different chain, so its untouched signature tests the canonical verifier while a fresh bool signature tests Weir's stricter callback policy.

Time-dependent tests use Foundry's clock accessor around `vm.warp` to avoid Solidity's assumption that a transaction's timestamp is constant. Stipend tests explicitly mark the consumer, signer or token as cold before delivering the callback.

## Local review considerations

The review traced every production entry point through caller checks, state changes, snapshots, transfer accounting, and request replay handling. It checked the internal JSON encoder, UTF-8 validator, copied attestation digest, immutable configuration, rate/balance arithmetic, bond rounding, zero-amount branches, asynchronous exits, and same-token IMD funding. Exact outgoing transfers are checked after CEI updates. Incoming principal/bonds are credited only after a verified pull, under the shared guard. Pending requests cannot be reopened by a late callback or reused Intake ID.

The signed oracle request UUID and the Intake receipt ID are distinct values, as the protocol reference specifies. The result callback pairs the answer with its pending stream by the receipt ID the Intake passes and consumes the signed UUID; the attestation tests and the conformance test deliver attestations whose UUID differs from the receipt, and check that a consumed UUID cannot settle a second stream and that an unknown receipt is refused even with a valid signature. The permissionless `submitAttestation` keeps the `a.requestId == stream.requestId` association, the only one it can authenticate, and the README says what that means for recovery. The reference's mutable configuration and failure-hook recommendations were superseded by the explicit immutable v2 design.

The immutable oracle signer and Intake are trusted external dependencies. Exact-transfer and non-rebasing token behavior is assumed; mutable malicious assets can invalidate custody assumptions. Holding-based gates are not resistant to borrowed holdings or multiple identities. Repeated eligible disputes can consume sponsorship, and successful rulings preserve ordinary client controls afterward. These are properties of the requested design, not powers added to the implementation.

No live-chain fork, paid oracle request, Slither, Mythril, deployment, source publication, or independent audit was performed. A token that permanently blocks a payout can permanently prevent enforcement or bond release. A `Ruled` stream has no timeout or independent bond claim. A missing result can be expired after the timeout, subject to successful token payout. The current live oracle's signed UUID cannot be submitted through `submitAttestation`; there is no permissionless resubmission recovery today.

## Revision findings

### Earlier round

The supplied `Proof_0ec5e391c648.t.sol` was copied unchanged into scratch space and run: it failed with `AttestationRequestMismatch()`, as reported. Its expected success was disputed in that round's `.imd-responses.json`. The assignment expressly requires `a.requestId == stream.requestId` for permissionless submission; the proof supplied a distinct UUID with no authenticated relation to the stored receipt, and removing the equality check would let a stranger settle a dispute with an unrelated question paid for in this contract's name. The required 24-hour relative-window body is retained.

### This round

All seven reports were reproduced on the starting tree before any change: the two supplied proofs failed as described, and the five scratch scenarios (bond inflation, exact-allowance block, fund drain, blocked disputer, Weir as recipient) behaved as the reviewer said.

**Bond inflation (5a85625d).** Reproduced: a 99,000e6 deposit after a 50e6 quote made the recipient's dispute pull 5,000e6, and a 20-wei deposit made an exactly-approved dispute revert. Fixed with `dispute(uint256,string,uint256 maxBond)`, which reverts `BondExceedsLimit` when the bond at execution exceeds the limit; the two-argument form is kept for the approved ABI and documented as unbounded. `WeirRevision` covers both scenarios and the knowing retry at the inflated bond.

**Records against a non-consenting recipient (9dfcd6fc).** Reproduced with the proof. Fixed by recipient acceptance: `accept(id)`, a first withdrawal or the recipient's own dispute sets `acceptedAt(id)`, and `_rule` writes `records` for both parties only when it is set. The dispute itself is not gated on acceptance: the second proof of this round has a client dispute a stream whose recipient never acts and requires it to succeed, and the reviewer offered "counted in records" as the alternative. A ruling on an unaccepted stream still settles the bond and principal and emits `Verdict`, but counts for nobody, which also removes the client's farmed win. The invariant model mirrors this.

**Hard-coded oracle price (21fa62ba).** Reproduced with the proof. `_request` now reads `intake.priceOf(ORACLE_ACTION, imd)` and uses it for the fund test, the pull, the approval, the request amount and the exact-debit check; `oraclePrice()` exposes it. `ORACLE_PRICE` stays as the documented launch price; `MAX_ORACLE_PRICE` (`5e18`) bounds what a dispute pays, and a zero price (action not sold) reverts `OraclePriceOutOfRange`. The mock Intake gained a settable price.

**Cold callback over 150,000 gas (3a27c1ca).** Reproduced: 155,222 gas in the callee frame on the starting tree, measured with `vm.lastCallGas`. The reentrancy guard on `onOracleResult` and `submitAttestation` was removed, since they move no tokens and can only staticcall the signer, which brings the frame to **152,131** gas (the four `WeirReview` measurements including caller overhead are about 156,100). The remaining excess is storage: consuming the UUID, the ruling, the state and two previously empty record slots, all of which the assignment requires at ruling. Getting under 150,000 would mean packing `ruling` beside `state` by reordering the approved `Stream` struct, which this revision did not do; the 150,000 figure comes from the tests assignment, not from this one or the approved workflow, whose stipend is 200,000.

**Free court-fund drain (7f3d6492).** Reproduced; not changed. The brief specifies a permissionless fund with no quota paid "when fund >= price, else by the disputer", and the suggested mitigation (make a zero-bond disputer pay) does not alter the economics: a bond is returned to the winner, so two addresses one person controls recover it whatever its size, and the holding is never spent. The README now states that a sponsored fund can be spent down by any eligible pair at the cost of gas.

**Blocked disputer locks Disputed (2d563820).** Reproduced: with the token refusing the disputer, the failure callback returned false and `expireDispute` reverted, leaving the client's principal locked. Fixed with `_pushOrDefer`: a payout the token reverts is credited to `claimable(token, account)` (`PayoutDeferred`) and collected later with `claim(token)`; the transition completes regardless. It is used by `onFailure`, `expireDispute` and both payouts of `enforce`, so the `Ruled` lock documented last round is gone too. A transfer that succeeds with the wrong amount still reverts. Deferred amounts are tracked in `unclaimed(token)` and included in the solvency check and in every test's backing assertion.

**Weir as recipient (44effbba).** Reproduced; `createStream` now rejects `address(this)` with `InvalidRecipient`.

**Unquoted note in the question (667d13af).** Not changed: the question template is fixed verbatim by the approved workflow. The README now states the consequence.

Production changes are confined to `src/Weir.sol`; the compiler settings, dependencies and the attestation library are unchanged, and the ABI export was regenerated.
